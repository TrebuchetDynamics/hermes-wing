# Hermes Agent: reference architecture study for Hermes Wing

## Scope and evidence

- **Audience:** Wing design and roadmap maintainers; this is research, not implementation approval.
- **Reference:** `hermes-agent/` at `158fd638da1629c8e62caf9ade1515d162def8ab`; checkout was clean when inspected. Analysis timestamp: `2026-10-04T00:08:05Z` (UTC, obtained with `date`). This is evidence of that checkout, not the installed Agent, latest release, or any advertised live host.
- **Method:** Understand Anything at `1d7418b8abfa543744ae029e63a482aee03f9022`; inspected `project-scanner`, `file-analyzer`, `architecture-analyzer`, `tour-builder`, and `graph-reviewer`. Applied their scan → grounded file summaries/imports → layers → topology-informed tour → deterministic graph review workflow sequentially. No UA agents or scanners were launched against upstream, and no Agent modules were imported or executed.
- **Read-only boundary:** no upstream writes, installs, hooks, tests, services or live API calls. Tests below were **inspected, not executed**. No user configuration, environment files, logs, runtime transcripts or secrets were inspected.
- **Wing authority:** [API and state](../../adr/api-and-state.md) and [runtime and delivery](../../adr/runtime-and-delivery.md) remain binding. Wing is the Flutter client; Wing Link is host management, not an Agent proxy or shadow backend. ROADMAP and all existing implementation/docs were left unchanged.
- **Artifacts:** [curated graph](agent-graph.json); 49 source/test/document nodes, 168 evidence-backed edges, 8 layers and 10 tour steps. Paths are relative to the Wing root and IDs start with `agent:`. This separate research graph is **not a Wing dependency graph**.

**Evidence labels:** “Implemented source” means observed code; “Tests inspected” means read assertions/fixtures, not green execution; “Runtime unknown” means qualification is still needed; “Recommendation” means proposed Wing work, not a shipped feature or accepted roadmap change. Negative API statements below refer to the inspected advertisement/route table, not every possible Agent extension or future release.

## Strongest design findings

1. **Agent has two materially different web surfaces.** The external aiohttp adapter advertises a machine-readable HTTP data plane. `serve`/`dashboard` use FastAPI administration plus native JSON-RPC/PTY transports. Similar paths and a shared agent core do not make their origins, tokens, or contracts interchangeable (§1).
2. **Session, run, runtime RPC session and profile are different identities.** Profile names/session IDs cannot be globally keyed in Wing. Model-lock and compression lineage also affect which resource a subsequent turn actually uses (§2–3).
3. **Disconnect semantics depend on the chosen route.** `/v1/runs` supports a separately subscribed SSE stream; session chat streaming interrupts on disconnect; native WS sessions detach or reap according to ownership and grace. “Detached run” must be an explicitly qualified contract, not a property inferred from SSE or WebSocket (§3).
4. **Stop acknowledgement is not a terminal outcome.** HTTP returns `stopping`; an uncooperative turn can still complete successfully. Native interruption cancels broader owning-session work through different handlers (§4).
5. **Implemented does not mean advertised or Wing-safe.** Job CRUD routes exist while `jobs_admin` is false and job endpoints are absent from the advertisement. Native config/profile/Project/skill/audio administration exists without becoming external HTTP capability support (§1, §6–9).
6. **Source outranks even nearby guides.** The cron guide says `skip_memory=True`; the inspected scheduled-agent constructor explicitly uses `skip_memory=False`. This is an evidence discrepancy, not permission to rewrite upstream or a runtime assertion (§9).

## 1. APIs, transports and native web versus advertised HTTP

**Implemented source.** [gateway/platforms/api_server.py](../../../hermes-agent/gateway/platforms/api_server.py) (lines 67–102, 1745–1790, 2537–2575) defines the external aiohttp adapter. Its `/v1/capabilities` explicitly describes `server_agent`, server-side tool execution and `split_runtime: false`. Advertised operations include model options, HTTP chat/responses, run submission/status/SSE/stop/steer/approval, session CRUD/messages/fork/chat/model lock, skills/toolsets reads and conditional browser control. Static flags explicitly deny `admin_config_rw`, `jobs_admin`, `memory_write_api`, `audio_api` and `realtime_voice`. Browser-control discovery separately distinguishes protocol support from enabled state.

**Implemented source.** [hermes_cli/web_server.py](../../../hermes-agent/hermes_cli/web_server.py) (lines 366–498 and router mounting) is a FastAPI serve/dashboard host with its own session-token/auth middleware. [hermes_cli/web_routers/chat_ws.py](../../../hermes-agent/hermes_cli/web_routers/chat_ws.py) (lines 438–612) exposes `/api/pty` and `/api/ws`; the latter delegates directly to `tui_gateway.ws.handle_ws`. [tui_gateway/ws.py](../../../hermes-agent/tui_gateway/ws.py) (lines 1–4, 295 onward) reuses stdio dispatch and preserves native JSON-RPC framing. Multiple newline-delimited JSON messages can be coalesced inside one WS frame. [Native web guide](../../../hermes-agent/web/AGENTS.md) says dashboard chat embeds the real Ink TUI and distinguishes headless `serve` from the SPA. That upstream UI constraint does not prohibit Wing's independent Flutter chat UI.

**Tests inspected.** [tests/gateway/test_session_api.py](../../../hermes-agent/tests/gateway/test_session_api.py) (test_capabilities_advertises_session_control_surface) asserts exact methods/paths, not merely a version. [tests/hermes_cli/test_web_server.py](../../../hermes-agent/tests/hermes_cli/test_web_server.py) covers the separate FastAPI surface; [tests/tui_gateway/test_protocol.py](../../../hermes-agent/tests/tui_gateway/test_protocol.py) (test_server_request_round_trip_uses_response_frame) covers native peer-to-peer RPC. These suites use fixtures and many mocked agent components; they do not prove a remote Flutter client works.

**Runtime unknown.** Installed origins/listeners, TLS/CORS, native WS authentication mode, available operation grants and current protocol contracts were not queried. The capability flags above must be refreshed from the actual profile endpoint before Wing enables an operation.

**Recommendation.** Maintain an operation matrix including surface, origin, auth type, exact method/path or RPC, identity inputs, response schema, cancellation/reconnect behavior and qualification status. Keep native web reads and native lifecycle protocol separate from advertised HTTP. Do not send Agent API traffic through Wing Link, reuse a management credential, infer native admin rights from an HTTP API key, or synthesize Agent capabilities.

## 2. Profiles and isolation

**Implemented source.** [hermes_constants.py](../../../hermes-agent/hermes_constants.py) (get_hermes_home, hermes_home_key, process-home helpers) resolves context-local home separately from launch/process home. [agent/secret_scope.py](../../../hermes-agent/agent/secret_scope.py) (set_multiplex_active, scoped credential resolution) binds secrets through context variables and fails closed when multiplexing is active without appropriate scope. [hermes_cli/profiles.py](../../../hermes-agent/hermes_cli/profiles.py) owns profile enumeration, creation, clone exclusions and tombstones. [tui_gateway/server.py](../../../hermes-agent/tui_gateway/server.py) (_profile_scoped and profile runtime helpers) binds RPC calls from a live session or an explicit profile. Root/area guides require home, secret and terminal scope together, including teardown, tickers and child processes—not just during a model turn.

**Implemented source.** [gateway/platforms/api_server.py](../../../hermes-agent/gateway/platforms/api_server.py) (lines 1586–1608; profile-prefix middleware) uses profile-bound Bearer authentication for `/p/<profile>/...`; named profiles cannot fall back to the launch key. A prefix must resolve to a served profile. These are configuration/state/credential boundaries, **not proof of an OS sandbox or mutually untrusted-tenant isolation**.

**Tests inspected.** [tests/gateway/test_multiplex_api_server_routing.py](../../../hermes-agent/tests/gateway/test_multiplex_api_server_routing.py) (test_unserved_prefix_is_rejected; test_profile_is_bound_into_session_vars); [tests/tui_gateway/test_secondary_profile_model_and_key.py](../../../hermes-agent/tests/tui_gateway/test_secondary_profile_model_and_key.py) (both tests); [tests/hermes_cli/test_web_routers_destructive_profile_scope.py](../../../hermes-agent/tests/hermes_cli/test_web_routers_destructive_profile_scope.py) (test_destructive_route_refuses_an_unnamed_profile_while_multiplexing; test_named_profile_is_the_only_one_touched). The latter checks selected destructive routes; it is not a universal authorization guarantee for every native route.

**Runtime unknown.** Served profile roster, deletion/recreation behavior seen by Wing, token rotation and scope across host shutdown have not been exercised.

**Recommendation.** Key Wing state by canonical Agent origin + profile identity + relevant resource identity, not profile display name alone. Carry explicit profile identity on reads and writes. Clear stale approvals/run associations when origin/profile changes. No global `profile use`, native “active profile” write, borrowed profile key, or Wing-owned profile workdir. Qualification should include two profiles with repeated resource IDs and A→B→A transitions.

## 3. Sessions, runs, continuity and reconnect

**Implemented source.** [hermes_state.py](../../../hermes-agent/hermes_state.py) (SessionDB facade) is the canonical persistence seam. [gateway/platforms/api_server.py](../../../hermes-agent/gateway/platforms/api_server.py) (session routes and session model-lock handler) separates stored conversation resources from a turn. [gateway/platforms/api_server_runs.py](../../../hermes-agent/gateway/platforms/api_server_runs.py) (_RunLaunch, _handle_start_run, _handle_get_run, _handle_run_events) gives execution a run ID distinct from its selected conversation/session; approval scope is per run, not conversation. Session chat also creates run control state. Stored model locks and actual served provider/model are distinct from a user's requested metadata.

**Implemented source.** HTTP run events have sequence IDs, bounded backlog and `Last-Event-ID` replay; an uncovered gap produces `replay.truncated`. Native replay in [tui_gateway/event_replay.py](../../../hermes-agent/tui_gateway/event_replay.py) uses per-session `seq` and a process epoch. [tui_gateway/methods_session.py](../../../hermes-agent/tui_gateway/methods_session.py) (lines 2584–2598) returns `truncated`, `epoch`, `latest_seq` and `open_requests`; reset watermarks on an epoch change and refetch authoritative state after gaps.

**Implemented source.** [gateway/platforms/api_server_runs.py](../../../hermes-agent/gateway/platforms/api_server_runs.py) (_handle_run_events and transport sweeping) permits independent `/v1/runs` subscriptions without tying execution to a single event subscriber. By contrast [gateway/platforms/api_server.py](../../../hermes-agent/gateway/platforms/api_server.py) (lines 3755–3784) interrupts a session chat stream's live execution on disconnect/cancellation. [tui_gateway/ws.py](../../../hermes-agent/tui_gateway/ws.py) (lines 443–465) tears down owning close-on-disconnect sessions or parks/detaches others for the orphan-reaper grace period. Native parking is not an unlimited background-job guarantee.

**Implemented source.** [gateway/platforms/api_server_run_idempotency.py](../../../hermes-agent/gateway/platforms/api_server_run_idempotency.py) (RunIdempotencyStore) provides scoped SQLite reservations, changed-payload conflicts and status persistence, with a disclosed in-memory fallback if storage is unavailable. [gateway/platforms/api_server_runs.py](../../../hermes-agent/gateway/platforms/api_server_runs.py) (_idempotency_capabilities and hydration) reports actual idempotency properties; a dead owner of a nonterminal persisted run becomes `interrupted`. A durable receipt does not resurrect execution or preserve an in-memory SSE backlog.

**Tests inspected.** [tests/gateway/test_api_server_runs.py](../../../hermes-agent/tests/gateway/test_api_server_runs.py) (test_reconnect_receives_exactly_missed_events_and_terminal; test_changed_payload_conflicts; test_restart_durability_and_terminal_semantics; test_direct_status_hydrates_after_adapter_restart; test_dead_owner_nonterminal_status_becomes_interrupted); [tests/gateway/test_session_api.py](../../../hermes-agent/tests/gateway/test_session_api.py) (test_session_messages_returns_compression_ancestors; test_session_chat_stream_disconnect_keeps_control_refs_until_executor_finishes; model-lock reuse tests); [tests/tui_gateway/test_tui_gateway_event_replay.py](../../../hermes-agent/tests/tui_gateway/test_tui_gateway_event_replay.py) (FIFO/byte-budget/oversized-event truncation tests). Mock-backed reconnect tests are source evidence, not platform suspension qualification.

**Runtime unknown.** Run retention, durable-store health, gateway restarts, mobile suspension, browser tab restoration and expired replay buffers need live qualification on the unmodified supported runtime.

**Recommendation.** Model transport health, conversation selection, execution state, pending human request and server persistence separately. Reconcile status and transcript after reconnect; deduplicate by server sequence within the correct identity/epoch, not message text. A detached-run roadmap item should specify the advertised run contract and tested suspend/reconnect/restart outcomes. Do not silently replay mutations, prompts or approvals. Do not apply the run-submission idempotency guarantee to unrelated administration or native RPCs.

## 4. Stop, steering and terminal outcomes

**Implemented source.** [gateway/platforms/api_server_runs.py](../../../hermes-agent/gateway/platforms/api_server_runs.py) (lines 1253–1274) checks owned run state, returns terminal state unchanged, rejects inactive control and otherwise returns **`stopping`** after requesting a hard interrupt. Actual execution settlement remains authoritative. [agent/interrupt_compat.py](../../../hermes-agent/agent/interrupt_compat.py) (lines 22–55) calls a real hard-interrupt ABI when available, with a legacy interrupt fallback.

**Implemented source.** [tui_gateway/methods_session.py](../../../hermes-agent/tui_gateway/methods_session.py) (lines 2366–2397) handles native `session.interrupt` with session/hosted-task identity and retires crash-recovery markers to avoid restarting deliberately stopped work. [tui_gateway/session_lifecycle.py](../../../hermes-agent/tui_gateway/session_lifecycle.py) (_interrupt_session_turn, lines 686 onward) handles owning-session delegation fanout; detached background units need explicit cancellation beyond the main turn. Native `interrupted` acknowledgement is still not proof that every subprocess or remote provider has stopped.

**Tests inspected.** [tests/gateway/test_api_server_runs.py](../../../hermes-agent/tests/gateway/test_api_server_runs.py) (test_completion_wins_before_uncooperative_stop_is_acknowledged; test_stop_then_steer_rejects_retained_agent_ref; test_expired_live_run_drops_transport_but_keeps_control_state); [tests/tui_gateway/test_session_interrupt_cancels_background_review.py](../../../hermes-agent/tests/tui_gateway/test_session_interrupt_cancels_background_review.py) (test_stop_interrupts_a_review_running_after_the_turn_finished). The completion-race assertion deliberately preserves a successful late result after provisional stop.

**Recommendation.** Render stop-requested separately from stopped/interrupted/completed/failed. Disable steering once stopping; do not discard a real late completion or mark success as cancelled locally. Keep each transport's stop handler behind its exact contract and preserve outcome-unknown UI after timeout. Test queued, running, pending-approval, post-turn review and expired-event-buffer stop cases.

## 5. Approvals and server-originated human requests

**Implemented source.** [gateway/platforms/api_server.py](../../../hermes-agent/gateway/platforms/api_server.py) (lines 107–124) redacts flagged commands and advertises allowed choices in `approval.request`. [gateway/platforms/api_server_runs.py](../../../hermes-agent/gateway/platforms/api_server_runs.py) (_make_approval_notify and _handle_run_approval) binds approval settlement to an owned run and request ID; scoped room grants restrict choices to once/deny. Permanent/session permission expansion cannot be inferred from an ordinary prompt or from Wing Link grants.

**Implemented source.** [tui_gateway/server_requests.py](../../../hermes-agent/tui_gateway/server_requests.py) (lines 1–32, advertise, resolve_response, cancel, open_requests) uses **peer-to-peer JSON-RPC requests and response frames**, not only notification + `approval.respond` pairs. A native WS client must advertise `client.capabilities {server_requests: true}` on each connection to be answerable. Reconnect snapshots carry open requests independently of event replay, and cancellation uses `request.cancel`. Legacy methods coexist in the inspected tests; they do not make the newer request protocol optional for every prompt.

**Tests inspected.** [tests/gateway/test_api_server_runs.py](../../../hermes-agent/tests/gateway/test_api_server_runs.py) (test_approval_resolve_all_is_scoped_to_target_run; test_approval_event_choices_follow_backend_capabilities); [tests/tui_gateway/test_protocol.py](../../../hermes-agent/tests/tui_gateway/test_protocol.py) (test_live_session_payload_replays_open_requests; test_server_request_fails_fast_for_a_ws_client_that_never_advertised; test_server_request_waits_for_a_ws_client_that_advertised; settlement/cancel tests). These assert correlation, connection negotiation and scope, not device-local sensitive-write approval.

**Recommendation.** Native lifecycle qualification must include bidirectional request handling and “not shown here”/cancel/timeout outcomes, not just outgoing RPC calls. Bind prompt UI to origin/profile/runtime session/run/request/transport generation as appropriate. Refresh open requests on reconnect, reject stale replies and avoid auto-answer or replay. Unknown secret/sudo/vault prompts must fail safely or use a reviewed secure UI, never be logged or silently coerced into command approvals.

## 6. Projects and directory assignment

**Implemented source.** [hermes_cli/projects_db.py](../../../hermes-agent/hermes_cli/projects_db.py) (lines 23–55, Project/folder operations) owns per-profile `projects.db`, multiple folders and a primary folder. [tui_gateway/methods_projects.py](../../../hermes-agent/tui_gateway/methods_projects.py) (lines 27–120) provides profile-scoped `projects.*` CRUD/folder operations, but accepts native host paths and also exposes `projects.set_active`. [hermes_cli/web_routers/profiles.py](../../../hermes-agent/hermes_cli/web_routers/profiles.py) (/api/profiles/projects/tree) provides a native presentation/read surface. No corresponding Project CRUD entry is present in the inspected external `_CAPABILITY_ENDPOINTS` table.

**Tests inspected.** [tests/hermes_cli/test_projects_db.py](../../../hermes-agent/tests/hermes_cli/test_projects_db.py) (test_per_profile_isolation; create/dedup/archive tests); [tests/tui_gateway/test_projects_rpc.py](../../../hermes-agent/tests/tui_gateway/test_projects_rpc.py) (test_projects_reads_are_scoped_to_the_requested_profile; test_projects_tree_is_scoped_to_the_requested_profile; folder/create tests).

**Runtime unknown.** There is no exercised remote Flutter flow that translates approved directory handles into a safe explicit Project transaction. Native path normalization/CRUD does not prove revocable directory grants, canonical containment or permission to disclose host paths.

**Recommendation.** Keep Project assignment a contract gap until an unmodified Agent API or approved fixed operation meets Wing's explicit identity and directory-grant requirements. Do not call global `projects.set_active`, send arbitrary native paths from remote Wing, or create a Wing-owned Project catalog/workdir. If a supported fixed Project operation is later approved, Wing Link may translate a locally approved opaque handle only inside that operation; current compatibility permissions are not expanded by this study.

## 7. Configuration, provider/model and Persona administration

**Implemented source.** [hermes_cli/web_routers/config_env.py](../../../hermes-agent/hermes_cli/web_routers/config_env.py) (lines 80–156, 259–342) exposes native config/schema/env administration. Config PUT deep-merges incoming fields over a strict disk read under `_CONFIG_MUTATION_LOCK` and returns `ok`; [hermes_cli/config.py](../../../hermes-agent/hermes_cli/config.py) (save_config and config write helpers) owns persistence. These inspected paths do not expose the expected-resource-revision transaction required by Wing's provider ADR. In-process RMW serialization is not proof of protection against another CLI process. Credential-specific APIs must be reviewed individually; the native surface includes secret reveal behavior and cannot be treated wholesale as Wing-safe administration.

**Implemented source.** [hermes_cli/web_routers/profiles.py](../../../hermes-agent/hermes_cli/web_routers/profiles.py) (lines 951–1055) has native profile/SOUL/model operations. These do not appear as equivalent external HTTP profile/Persona CRUD in the inspected capability table. Session model lock and read-only model catalog are different operations from changing existing-profile provider credentials.

**Tests inspected.** [tests/hermes_cli/test_config_rmw_lock.py](../../../hermes-agent/tests/hermes_cli/test_config_rmw_lock.py) (both tests) races writers inside the FastAPI process and asserts preservation of both fields; it does not assert expected revisions, crash-safe mutation receipts or cross-process CAS. [tests/hermes_cli/test_web_routers_destructive_profile_scope.py](../../../hermes-agent/tests/hermes_cli/test_web_routers_destructive_profile_scope.py) checks explicit profile targeting. [tests/tui_gateway/test_secondary_profile_model_and_key.py](../../../hermes-agent/tests/tui_gateway/test_secondary_profile_model_and_key.py) checks selected profile model/key behavior.

**Recommendation.** Keep persistence, provider validation/inference and runtime activation/restart as separate user outcomes. Retain existing-profile provider/Persona unavailable states where Wing's contract requirements are missing. The setup catalog exception remains read-only and does not expand write rights. No native broad config editor, direct-file writes or Agent patches should be added to fill gaps.

## 8. Tools, skills and memory

**Implemented source.** [tools/registry.py](../../../hermes-agent/tools/registry.py) (discovery, check_fn_cache_scope and dispatch) registers/discovers tools, gates readiness and scopes availability caches. [model_tools.py](../../../hermes-agent/model_tools.py) (get_tool_definitions and selection helpers) combines selected toolsets, runtime availability and role/session context. Tool inventory is not identical to the schemas exposed to a current run. External HTTP advertises skills/toolsets reads, while native administration exists in [hermes_cli/web_routers/tools.py](../../../hermes-agent/hermes_cli/web_routers/tools.py) and [hermes_cli/web_routers/skills.py](../../../hermes-agent/hermes_cli/web_routers/skills.py); a read catalog is not installation, enablement or secret-write authorization.

**Implemented source.** [agent/memory_manager.py](../../../hermes-agent/agent/memory_manager.py) (provider lifecycle/tool exposure) owns provider hooks and schema gates. [gateway/platforms/api_server_memory_sessions.py](../../../hermes-agent/gateway/platforms/api_server_memory_sessions.py) retains a MemoryManager across rebuilt HTTP turn agents using exclusive checkout keyed by home/session. The inspected HTTP flag `memory_write_api: false` does not mean Agent lacks memory: native provider configuration lives in [hermes_cli/web_routers/memory_providers.py](../../../hermes-agent/hermes_cli/web_routers/memory_providers.py) and model tools can affect Agent-owned memory under their own controls.

**Tests inspected.** [tests/tools/test_registry.py](../../../hermes-agent/tests/tools/test_registry.py) (registration/dispatch, availability, package discovery tests); [tests/gateway/test_api_server_memory_sessions.py](../../../hermes-agent/tests/gateway/test_api_server_memory_sessions.py) (test_manager_survives_across_requests_and_is_exclusive_per_home); [tests/hermes_cli/test_web_server.py](../../../hermes-agent/tests/hermes_cli/test_web_server.py) (native memory configuration tests).

**Recommendation.** Display installed/registered, selected, available, permission-blocked and unavailable states separately where supplied authoritatively. Refresh inventory after a capability/scope change without rewriting an existing conversation's toolset or system prompt in Wing. Treat memory as Agent-owned; do not locally extract/persist a second memory corpus or manufacture writes from a read-only catalog. Explicitly label deferred-versus-current-session effects where the Agent contract provides them.

## 9. Schedules and jobs: a discovery mismatch

**Implemented source.** [gateway/platforms/api_server.py](../../../hermes-agent/gateway/platforms/api_server.py) (lines 74, 1780–1787, 3838–3964) registers job list/create/read/update/delete/pause/resume/run handlers. Their shared guard checks Bearer auth, drain state and cron availability, **not a `jobs_admin` feature grant**. Yet the inspected advertisement sets `jobs_admin: false` and omits jobs endpoints. Source and tests therefore establish implementation, but do not establish capability-discovered Wing support. This is an intentional evidence distinction, not a vulnerability finding or a request to enable probing.

**Implemented source.** [cron/jobs.py](../../../hermes-agent/cron/jobs.py) (profile store resolution) owns per-profile schedule storage. [cron/scheduler_provider.py](../../../hermes-agent/cron/scheduler_provider.py) (profile-scoped sequential ticker) binds profile scope for scheduling. [hermes_cli/web_routers/cron.py](../../../hermes-agent/hermes_cli/web_routers/cron.py) has a separate native schedule/execution-history surface. [cron/scheduler.py](../../../hermes-agent/cron/scheduler.py) (lines 2525–2535) constructs the scheduled AIAgent with **`skip_memory=False`** and `skip_background_review=True`. [cron/AGENTS.md](../../../hermes-agent/cron/AGENTS.md) (line 83) and [agent/AGENTS.md](../../../hermes-agent/agent/AGENTS.md) (line 126) instead say cron skips memory; their guidance is stale for this observed constructor. No complete cron-memory runtime trace/test was executed, so do not claim every cron mode or provider has been qualified.

**Tests inspected.** [tests/gateway/test_api_server_jobs.py](../../../hermes-agent/tests/gateway/test_api_server_jobs.py) (test_auth_required_create_job; test_auth_passes_with_valid_key; test_create_job_reports_saved_but_unregistered); [tests/cron/test_cron_multiplex_desktop_ticker_scope.py](../../../hermes-agent/tests/cron/test_cron_multiplex_desktop_ticker_scope.py) (ticker gate, routed-scope and dashboard run-now tests). Also inspected [tests/hermes_cli/test_web_server_cron_profiles.py](../../../hermes-agent/tests/hermes_cli/test_web_server_cron_profiles.py) (profile registration and saved-but-unregistered tests), which is supplementary evidence outside the curated graph.

**Recommendation.** Keep advertised HTTP job administration disabled when exact discovery is missing, even if a guessed route happens to respond. A qualified native read path may improve schedule visibility but does not authorize mutation or a Wing Link schedule adapter. Show saved/registered/enabled/claimed/running/terminal states separately. Job identity includes profile and origin; “saved” does not establish scheduler registration or delivered output. Live qualification should cover duplicate job IDs across profiles, forced run of a paused job, missed occurrences, shutdown and registration failure.

## 10. Roadmap recommendations, not accepted changes

| Priority | Proposed Wing design/research task | Acceptance evidence before any support claim |
|---|---|---|
| P0 | Contract ledger separating external HTTP, native RPC and native REST | Exact discovery/auth/resource scope and parser tests; no broad-version or admin inference |
| P0 | Run/session/transport state reconciliation and truthful stop UI | Stop/completion race, SSE disconnect per route, replay gap/epoch change, expired buffers and process restart |
| P0 | Native human-request protocol qualification | Connection capability advertisement, correlated response, wrong-session/old-connection refusal, open-request replay and cancellation |
| P1 | Profile-switch/isolation regression matrix | Origin/profile A→B→A, repeated IDs, credential rotation and profile delete/recreate; no borrowed credential |
| P1 | Read-only inventory fidelity | Tools readiness versus installed, schedule persistence versus registration, model requested versus served; authoritative refresh |
| P1 | Project assignment contract feasibility | Approved rooted handle → explicit Agent Project identity; no arbitrary paths, global active selection or shadow store |
| P2 | Sensitive administration acceptance research | Verify expected revisions, exact grants, write-only secrets, crash receipts, separate activation; leave unavailable otherwise |
| P2 | Per-platform detached-run and audio qualification | Real Android/web/desktop suspend and reconnect evidence; native audio routes alone do not satisfy advertised HTTP audio support |

No upstream implementation, patch, fork, general CLI bridge, domain proxy or direct-file mutation is recommended. Missing capabilities remain unavailable until supported unmodified contracts meet the living ADRs. Runtime qualification is proposed work requiring its own authorized isolated environment; it was **not performed here**.

## Graph construction and verification

The graph is curated, not exhaustive: only the named source/test seams and two guides are nodes. `imports` edges were extracted with Python AST from explicit imports, including function-local/relative imports; descriptions record the source line.
