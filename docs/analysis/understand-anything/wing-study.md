# Hermes Wing: current-source Understand Anything study

> Reference correction: [official Desktop authority](../../quality/official-desktop-reference.md). Prior Desktop source citations and parity conclusions in this document are withdrawn. Wing test results remain historical behavior evidence only.


## Verdict

Wing already has a substantial production Chat path, not just a navigation prototype. Its strongest design is the enforced separation between Agent-owned domain state and Wing Link host management, combined with explicit asynchronous ownership fences. The highest-value next work is **closing current-source qualification and acceptance gaps**, not replacing transports or adding a generic administration framework.

The concrete small code candidate found here is **readiness-report authorization drift**: some diagnostic predicates are weaker than the live channel gates. The largest maintenance risks are shared-state Dart part libraries, repeated owner/generation bookkeeping, and custom Markdown rendering. These are risk concentrations, not proof of broken runtime behavior or reasons for a broad rewrite.

## Design strengths worth preserving

### 1. Production seams align with the two-plane ADR

[lib/features/hermes_chat/providers/hermes_channel_provider.dart](../../../lib/features/hermes_chat/providers/hermes_channel_provider.dart) constructs `HermesApiChannel` with the secure detached-run store and composes the directory through injectable providers. [lib/core/hermes/client/hermes_api_client.dart](../../../lib/core/hermes/client/hermes_api_client.dart) is direct Agent transport; [lib/core/wing_link/wing_link_client.dart](../../../lib/core/wing_link/wing_link_client.dart) is separately typed management. On the host, [wing_link/internal/app/serve.go](../../../wing_link/internal/app/serve.go) exposes fixed operations, not session/run proxying. The assertions in [wing_link/internal/app/serve_test.go](../../../wing_link/internal/app/serve_test.go) include `TestManagementAPIUsesIndependentControlTokenAndDoesNotProxyHermes`; [wing_link/internal/app/architecture_boundary_test.go](../../../wing_link/internal/app/architecture_boundary_test.go) rejects forbidden domain-bridge fragments. The latter is a useful static guard, not a substitute for behavior tests.

### 2. Stale results are fenced before they enter caches, not just before painting

`_restoreSession` in [lib/core/hermes/channel/api_channel/hermes_api_channel_sessions.dart](../../../lib/core/hermes/channel/api_channel/hermes_api_channel_sessions.dart) lines 15–55 clears the old send target, exact-reads unknown sessions only when authorized and checks caller/selection ownership. `_fetchTurns` in [lib/core/hermes/channel/api_channel/hermes_api_channel_connection.dart](../../../lib/core/hermes/channel/api_channel/hermes_api_channel_connection.dart) lines 329–390 checks ownership before pagination/history/cache admission. [test/features/hermes_chat/gateways/hermes_gateway_session_restoration_test.dart](../../../test/features/hermes_chat/gateways/hermes_gateway_session_restoration_test.dart) lines 150–179 asserts exact older-session history, correct profile query, no replacement selection and zero mutations. [test/features/hermes_chat/gateways/gateway_selection_write_race_test.dart](../../../test/features/hermes_chat/gateways/gateway_selection_write_race_test.dart) covers delayed real preference writes and disposal/selection validity. Preserve both in-memory and storage-write fences.

### 3. Stop acknowledges uncertainty instead of equating socket cancellation with termination

`_confirmStoppedRun` / `_stopActiveTurn` in [lib/core/hermes/channel/api_channel/hermes_api_channel_messaging.dart](../../../lib/core/hermes/channel/api_channel/hermes_api_channel_messaging.dart) lines 2217–2374 require the captured run/session, terminal status and canonical history before releasing ownership. Failed or uncertain reads keep `hasUnreconciledRun`, blocking later sends. [test/core/hermes/channel/hermes_api_channel_tests/stop_outcome_tests.dart](../../../test/core/hermes/channel/hermes_api_channel_tests/stop_outcome_tests.dart) lines 77–166 asserts one submit/stop, rejects wrong IDs/nonterminal outcomes and requires zero replay. [lib/core/hermes/channel/approvals/hermes_approval_responder.dart](../../../lib/core/hermes/channel/approvals/hermes_approval_responder.dart) correlates Agent request IDs; [test/core/hermes/channel/hermes_api_channel_tests/native_approval_tests.dart](../../../test/core/hermes/channel/hermes_api_channel_tests/native_approval_tests.dart) specifies non-FIFO exact-ID behavior and replay rejection. Do not simplify this into a local cancel flag.

### 4. Long conversations separate canonical data from rendering budgets

[lib/features/hermes_chat/presentation/hermes_transcript_viewport.dart](../../../lib/features/hermes_chat/presentation/hermes_transcript_viewport.dart) starts with 100 turns, permits deliberate reveal, limits process-local anchors to 64 and requires unique turn IDs for reading recovery. [test/features/hermes_chat/screens/hermes_chat_window_test.dart](../../../test/features/hermes_chat/screens/hermes_chat_window_test.dart) covers large loaded history, long tool groups, duplicate/deleted anchors and canonical copy beyond the rendered window. [lib/features/hermes_chat/presentation/hermes_markdown_block_viewport.dart](../../../lib/features/hermes_chat/presentation/hermes_markdown_block_viewport.dart) separately virtualizes blocks inside large Markdown; [test/features/hermes_chat/presentation/hermes_markdown_block_viewport_test.dart](../../../test/features/hermes_chat/presentation/hermes_markdown_block_viewport_test.dart) checks far jumps, extent-cache invalidation and code-copy fidelity. Those are two different performance problems; merging them would conflate presentation with Agent pagination.

### 5. Administration distinguishes unavailable, empty and locally filtered

[lib/features/tools/screens/tools_screen.dart](../../../lib/features/tools/screens/tools_screen.dart) and [lib/features/schedules/screens/schedules_screen.dart](../../../lib/features/schedules/screens/schedules_screen.dart) keep writes hidden and offer exact, owner-fenced read refresh. Search is local; no matches is not an unavailable read. [test/features/tools/tools_search_ownership_test.dart](../../../test/features/tools/tools_search_ownership_test.dart) specifies replacement-client and same-frame grant roundtrips, stale completions and independent clear actions. [test/core/hermes/channel/hermes_inventory_refresh_admission_test.dart](../../../test/core/hermes/channel/hermes_inventory_refresh_admission_test.dart) checks real-channel admission before I/O, including selecting/disconnected states. [lib/core/hermes/channel/api_channel/hermes_api_channel_inventory.dart](../../../lib/core/hermes/channel/api_channel/hermes_api_channel_inventory.dart) reuses `canReadJobs` during bootstrap; [test/core/hermes/channel/hermes_jobs_bootstrap_authorization_test.dart](../../../test/core/hermes/channel/hermes_jobs_bootstrap_authorization_test.dart) exercises additional grants, query context and optional failure recovery.

### 6. Host access and activation fail closed

[wing_link/internal/workspaces/browser.go](../../../wing_link/internal/workspaces/browser.go) lines 105–206 re-resolves grants and traverses opened roots, returns folder names/opaque handles only and bounds scanning/listing. [wing_link/internal/workspaces/browser_test.go](../../../wing_link/internal/workspaces/browser_test.go) includes concurrent symlink/root replacement, revocation and device binding. [wing_link/internal/app/model_options.go](../../../wing_link/internal/app/model_options.go) projects bounded display-only catalog fields, fixes the upstream origin locally, rejects redirects/proxies and does not create credentials during reads; [wing_link/internal/app/model_options_test.go](../../../wing_link/internal/app/model_options_test.go) checks authority, identity, bounds and safe error output. [wing_link/internal/operation/journal_test.go](../../../wing_link/internal/operation/journal_test.go) specifies same-request replay, changed-payload rejection and interrupted-operation recovery without payload persistence. [wing_link/internal/release/updater_test.go](../../../wing_link/internal/release/updater_test.go) specifies verification, restart/health rollback and empty-key fail-closed behavior; [wing_link/internal/release/release_keys.go](../../../wing_link/internal/release/release_keys.go) currently has an empty production trust-key map. This is not signed distribution readiness.

## Proposed bounded slices and exit criteria

These are recommendations, not accepted assignments or new roadmap edits. Reuse existing cards/reviews where ROADMAP names them; do not duplicate ongoing work. Executor → independent tester → reviewer acceptance remains separate from a local green test command.

### A. P0: finish exact-session restoration acceptance, without reimplementation

- Scope: existing M2 restoration implementation and its outstanding independent acceptance; directory, channel recovery and selection cache only. Read [restoration runbook](../../../docs/runbooks/chat-session-restoration.md) first.
- Exit: independently run known/unknown page-two session recovery, unsupported/denied/not-found/malformed reads, A→B→A host/profile/client changes, delayed preference writes and draft races. Assert exact canonical tuple, zero creates/sends, no old selection rewrite and no wrong-owner history/cache admission. Repeat compiled Chromium at the named widths; report acceptance separately from device qualification.
- Small checks: `flutter test test/features/hermes_chat/gateways/hermes_gateway_session_restoration_test.dart test/features/hermes_chat/gateways/gateway_selection_write_race_test.dart test/features/hermes_chat/gateways/hermes_gateway_restoration_adversarial_test.dart test/features/hermes_chat/screens/hermes_chat_restoration_draft_race_test.dart --concurrency=1`; then build the deterministic web target before its restoration Playwright journey. Commands are proposed, not run by this study.

### B. P0: one actual production Chat journey on the already-selected mode

- Scope: qualify the current API-channel user outcome, preserving reviewed transcript/model-picker/export behavior. Do not substitute native-web qualification or another provider when target authentication is missing. See [production journey](../../../docs/runbooks/chat-production-journey.md) and [compatibility limits](../../../docs/runbooks/hermes-agent-release-compatibility.md).
- Prerequisites: owner-approved disposable unmodified Agent target, supported private target authentication, selected provider/model, harmless tool and network/cost limits. Missing credentials remain a real blocker; never collect them in task metadata or logs.
- Exit: real generated response, harmless tool/approval allow+deny, exact correlated approval, Stop terminal readback, controlled transport loss/reconnect and subsequent prompt with zero duplicate send. Record source/diff, SDK, named target and sanitized assertions, not private endpoint/transcript dumps. Tester repeats and reviewer accepts only the exercised targets.
- Deterministic baseline: `flutter test test/core/hermes/channel/hermes_api_channel_test.dart --concurrency=1` plus the compiled production journey before actual inference. A fixture cannot fulfill the live exit criterion.

### C. P1: align readiness rows with existing exact authorization

- Scope: only affected jobs/health/persona readiness predicates and their diagnostic tests. No new capability schema, operation, transport or UI state service.
- Exit: additional required grant missing, unsupported schema, wrong method/path and unsupported profile context all produce an unavailable/deferred report consistent with the live gate; allowed/read-only cases remain accurate. For each row compare operational authorization with reporting, not merely a broad feature flag. Verify that no report change issues requests or enables writes.
- Checks: `flutter test test/core/hermes/hermes_api_test.dart test/core/hermes/channel/hermes_jobs_bootstrap_authorization_test.dart --concurrency=1`, `flutter analyze`, and nearest Chat status/diagnostics regression. Add the smallest failing test first; the mismatch was not executed as a failing runtime test in this study.

### D. P1: one Android running→completed process-death return

- Scope: current secure detached-run store, directory activation and lifecycle on one named Android target after the supported M1 journey; no push or durable draft expansion.
- Exit: background, forced process death, relaunch, completed canonical history, expired/revoked credential and wrong-owner cases preserve the exact host/profile/session/run tuple and produce zero resend. Denied notification permission cannot make status unusable. Record device/OS/API and secure-store/pin behavior separately from Chromium viewport tests.
- Reuse [existing secure store](../../../lib/core/hermes/setup/secure_hermes_detached_run_store.dart) and [lifecycle](../../../lib/features/hermes_chat/screens/state/hermes_chat_lifecycle.dart); follow ROADMAP M2 retention and notification checkpoints only for their respective additions.

### E. P2: qualify one native output/accessibility path

- Scope: existing loaded-transcript save/copy on Android, native focus/IME and TalkBack; no artifact API, filesystem browser expansion or new render abstraction.
- Exit: explicit save/share cancel/denial, owner change before write, Unicode and bound enforcement, 200% text/reduced motion, keyboard/CJK IME and screen-reader operation. Saved loaded output matches existing redacted copy semantics. Do not label a browser download-start event as native save success.
- Checks: `flutter test test/features/hermes_chat/screens/hermes_chat_transcript_export_test.dart test/features/hermes_chat/presentation/hermes_markdown_block_viewport_test.dart --concurrency=1`; then matching device journey from [export runbook](../../../docs/runbooks/chat-transcript-export.md). Broader output/native acceptance remains distinct.
