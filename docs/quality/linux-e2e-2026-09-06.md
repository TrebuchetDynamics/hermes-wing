## Plain-line performance fix

User requested a fix for the 1 MB unbroken-line timeout. Evidence directory:
`/tmp/wing-text-fix.ksnlJa/`. Existing unrelated changes remain preserved.

### Root cause and change

A standalone parser probe processed the 1 MB line in about 24 ms. A minimized
native profile test using plain Flutter `Text`, without Markdown or selection,
took about 12.3 seconds to mount the same input. Selection enabled also took
about 12 seconds. The large-message viewport bounded its visible height but
still asked Flutter to lay out a single million-character wrapped paragraph.

`HermesRichText` now detects oversized single-line plain Markdown paragraphs,
splits their decoded display text at 2,048-grapheme boundaries, and uses a lazy
list so only visible chunks are laid out. Cached chunks refresh when the source
changes. Links, emphasis, code and other Markdown retain the existing renderer;
syntax is never split into separately parsed fragments. No Agent data, transport,
credentials, or persisted transcript content changes.

Selection operates on mounted chunks; chunk boundaries can introduce selection
breaks. The reader provides **Copy as text** for an exact full-source copy
independent of the viewport. This is a presentation change, not truncation.

### Regression and qualification

The minimized 100 KB widget regression failed before the fix because a rendered
text node held the entire source, and passed after the fix. Coverage now checks
bounded mounted text, exact full-source copy, reaching the final suffix by
scrolling, grapheme integrity, appending a streaming suffix, and returning from
plain-text chunking to rich Markdown and then short text.

The original 1 MB profile command completed after the fix with 12 mounts
(two warmups plus ten measured) and 20 update/scroll iterations in about
**11 seconds of test execution**. Mount p95 was **500.5 ms** and maximum
update/scroll time was **168 ms**. The command's three-minute limit was unchanged.

Added Linux profile-mode benchmark gates for this exact 1 MB line case:
mount p95 below **2 seconds**, update/scroll p95 below **500 ms**. Reran both
100 KB and 1 MB lines with the gates enabled:

The measurements include pumping/settling and alternating scrolling; they are

### New failing IME regression

yet a proven line-level engine fix. Ordinary key input/file selection, IME, and
lifecycle are separate cases so the IME failure cannot prevent the other checks
from running. No SDK patch, expectation relaxation or skipped regression hides it.
