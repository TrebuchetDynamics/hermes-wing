# Release Evidence Implementation Plan

> **For agentic workers:** Use executing-plans task-by-task. This plan does not authorize publishing, signing-key changes, tags, commits, or workflow dispatch.

**Goal:** Bind validation and platform qualification to immutable build inputs and the exact artifacts exercised.

**Architecture:** Extend existing release verification and receipt paths. Keep one manifest of build identity and artifact digests, with separately hashed qualification receipts; preserve current signature, archive, health, and rollback checks.

**Tech Stack:** Existing GitHub Actions workflows, Node.js 22 built-ins for proposed manifest tooling, Flutter 3.44.2, Go 1.26, existing shell verifiers and Dart tooling tests.

## Global Constraints

- Follow the [program](2026-09-04-conduit-adaptation-roadmap.md) and runtime/delivery ADR.
- A source SHA is insufficient when generated build inputs differ. Hash the actual inputs consumed by each build.
- Artifact digests identify bytes; signatures establish the configured trust chain. Neither substitutes for runtime qualification.
- No credentials, device serials, transcripts, private endpoints, or host paths in public manifests or receipts.
- No paid runs or releases are needed for local behavioral tests. New schema and filenames below are proposed interfaces.

## Task 1: Add an exact-input artifact manifest

**Files:** modify `.github/workflows/release-alpha.yml` and `scripts/verify_release_artifacts.sh`; create `scripts/release_evidence.mjs` and `test/tooling/release_evidence_test.mjs`; extend `test/tooling/release_workflow_contract_test.dart`.

**Current evidence:** The workflow validates source, builds separate target artifacts, downloads and verifies them, performs artifact smoke checks, and binds publication to `GITHUB_SHA`. Its Android build also rewrites `assets/config/termux_bootstrap.json` with release metadata before building; record those generated bytes.

**Proposed interface:** `release-evidence.json` schema version 1 contains:
source revision; source-dirty flag; build number/version; target; workflow run ID/attempt;
toolchain versions; SHA-256 for `pubspec.lock`, `package-lock.json`, `wing_link/go.mod`,
`wing_link/go.sum`, and generated bootstrap metadata when consumed; artifact
basename, byte size, SHA-256, and signing identity where relevant. Missing lock
files must be explicitly accounted for, not hashed as empty input.
The manifest excludes its own digest; a separate qualification index hashes the
manifest and receipts, avoiding circular hashing.

- [x] Define a bounded JSON schema and basename allowlist matching current release artifacts. Reject unknown schema versions, duplicate artifacts, path traversal, symlinks, missing required inputs, malformed hashes, and source/target mismatches.
- [x] Add Node built-in tests that create synthetic files in a temporary directory. A valid manifest verifies; changing one byte, lock digest, source revision, generated bootstrap digest, or build number fails. Supply actual emitted bytes to assertions rather than checking source strings.
- [x] Implement a local-only `release_evidence.mjs` verifier using Node built-ins. Keep hashing deterministic, validate file size before reading, and hash actual build inputs after dependency resolution and metadata generation.
- [x] Emit manifests beside each artifact set; make existing verification consume them. Preserve independent APK/AAB signature checks and archive containment checks.
- [x] Run `node --test test/tooling/release_evidence_test.mjs` and `flutter test test/tooling/release_workflow_contract_test.dart test/tooling/wing_link_distribution_contract_test.dart`. Expected: valid fixture accepted; all mismatches fail before artifact execution/publication.

## Task 2: Bind platform receipts to actual tested bytes

**Files:** modify `scripts/record_android_live_mic_receipt.sh`, `scripts/record_hermes_server_audio_receipt.sh`, `scripts/verify_release_artifacts.sh`, and `.github/workflows/release-alpha.yml`; update `docs/runbooks/android/release-handoff.md`, `docs/runbooks/android/live-mic-smoke.md`, and `docs/quality/evidence-matrix.md`. Extend tests from Task 1 and `test/tooling/evidence_matrix_contract_test.dart`.

**Proposed interface:** A qualification receipt contains manifest SHA-256, artifact basename/SHA-256, scenario ID, timestamp, platform/OS/device class, evidence kind (fixture, emulator, physical, native service), pass/fail/not-exercised result, and bounded limitations. An Android APK launch never qualifies a separately built AAB.

- [x] Test absent digest, mismatched APK, receipt from another revision/build, and a receipt claiming physical qualification with emulator evidence. Each must be rejected from the corresponding qualification claim.
- [ ] Capture the artifact digest at installation/execution time and verify it against the manifest. For installed Android packages verify the installed package identity; do not trust a manually entered filename. For split/store installs define the exact delivered set and record it separately.
- [x] Extend existing smoke receipts, including native macOS/Windows Wing Link version checks, to carry their own artifact digest. Retain narrow labels: version execution is not service qualification.
- [x] Generate one final qualification index only after every required artifact and smoke receipt has been downloaded. It binds repository/source/tag/workflow run+attempt, SHA-256 of `pubspec.lock`, `package-lock.json`, and `wing_link/go.sum`, every artifact size+digest, and every receipt size+digest plus exercised artifact digest. Publication depends on this final aggregator; the earlier host verification receipt is not the final release manifest.
- [x] Keep manual observations required for physical voice, but sanitize receipt fields rather than exporting spoken phrases. Audit current recorder inputs before changing schema; preserve old receipts as historical evidence, not silently upgraded receipts.
- [x] Implement a recorder binding Linux install/start/restart/health/rollback/uninstall observations to the exact bundle and Wing Link bytes. Failed activation must restore the previous verified artifact; live observation remains unexercised.
- [x] Run Node manifest tests, `flutter test test/tooling/release_workflow_contract_test.dart test/tooling/evidence_matrix_contract_test.dart`, `dart run scripts/check_evidence_matrix.dart`, and `git diff --check`.
- [ ] Update evidence classifications only after real platform runs. Record missing hardware/signing infrastructure as an evidence gap; local synthetic verification does not close that gap.

## Task 3: Make CI completeness explicit, then measure scaling

**Files:** modify `.github/workflows/hermes-platform-smoke.yml` and `.github/workflows/release-alpha.yml`; extend `test/tooling/release_workflow_contract_test.dart`; create `docs/quality/ci-timing.md`. Only if the measurement gate is met, create `scripts/plan_test_shards.mjs` and `test/tooling/test_shard_plan_test.mjs`.

**Interfaces:** One stable aggregate status succeeds only if every required job and expected test partition completed successfully. Optional platform jobs are explicitly classified. Missing, cancelled, timed-out, or unreported required jobs cannot yield success.

- [x] Define the required-job set for PR and release workflows and test aggregate success/failure/skipped/cancelled cases. Preserve the existing release dependency gates; do not change branch protection externally in this task.
- [x] Store redacted per-suite elapsed times and separate assertion failures, infrastructure failure, timeout, and result-finalization failure. Test runner exit zero without complete expected results is a failure.
- [ ] Collect ten representative successful CI runs before sharding. Proposed decision gate: median Flutter test phase exceeds 10 minutes or p95 exceeds 15 minutes, and test execution dominates rather than setup/build. These are planning thresholds, not observed timings.
- [ ] If the gate is unmet, record measurements and retain current execution. If met, partition standalone `*_test.dart` entrypoints deterministically by historical duration; never shard `part of` fragments as standalone tests. Unknown tests receive a conservative nonzero estimate.
- [ ] Test inventory union equals discovery exactly once: missing, duplicate, deleted, empty, and newly added tests; renamed tests; corrupted timing data; lane cancellation. Fail closed rather than silently dropping tests.
- [ ] Reuse an existing built artifact only for compatible lanes with matching target/toolchain/dependency identity. Do not assume Flutter unit/widget tests can use the iOS build-once/test-without-building technique. Keep production and deterministic E2E artifacts distinct.
- [ ] Run relevant tooling tests and, if created, `node --test test/tooling/test_shard_plan_test.mjs`. Record actual CI timings before changing lane count. Preserve stable aggregate naming through any matrix change.
